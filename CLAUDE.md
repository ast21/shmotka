# Шмотка — договорённости

## О проекте
- Что это: тема и шпаргалка готовых фрагментов daisyUI для личных проектов (идея #12 в IdeaHub). Общий вид для всех проектов,
  под проект меняется только акцент. Tailwind и daisyUI проект ставит сам — Шмотка их не содержит.
- Стек: Node 22, без рантайм-зависимостей. Tailwind CSS v4 + daisyUI 5 — peer- и dev-зависимости.
- Источник правды — `tokens/tokens.json`. `css/shmotka.css` генерируется `npm run build` и коммитится
  (проекты ставят пакет прямо из GitHub-тега, сборки при установке нет). Руками его не править.
- Проверки: `npm ci && npm run check` — актуальность `css/shmotka.css`, контраст в обеих темах для каждого акцента, тесты.
- Новый цвет или акцент — только через `tokens/tokens.json`; контраст ниже 4.5:1 для текста CI не пропустит.
- Шпаргалка `snippets/*.html`: первая строка `<!-- @snippet title="…" about="…" -->`, только классы daisyUI, Tailwind и утилиты Шмотки —
  без `<style>`, hex-цветов и палитры Tailwind (проверяет `test/snippets.test.mjs`). Новый фрагмент сам попадает на витрину.
- Правила для нейронок проектов — `docs/ai.md`; меняется вместе с темой и шпаргалкой.
- Деплой: релиз = тег `vX.Y.Z`; проекты подключают `npm i github:ast21/shmotka#vX.Y.Z`.
  Витрина `npm run site` → `site/dist` → Cloudflare Pages, проект `shmotka` (https://shmotka.pages.dev), `.github/workflows/pages.yml` после мержа.

## Как работаем (общее для всех проектов из ideahub-project-template)
- **Одна задача — один PR — одна версия.** Каждый PR добавляет новую запись сверху в `CHANGELOG.md`:
  `## X.Y.Z — ГГГГ-ММ-ДД — Короткое название`, строка хэштегов, пункты понятным языком для человека, а не для разработчика.
  X — большие перемены, Y — новая возможность, Z — исправления. До первого релиза для людей — `0.x.y`.
  Если в проекте есть файл с версией (`package.json`, `pyproject.toml`, `composer.json`), держи её такой же.
- Ветка → PR с заголовком `X.Y.Z: короткое название` → CI зелёный → **squash-merge** в `main`.
  В `main` получается один коммит на версию: `X.Y.Z: … (#N)`.
- После мержа `release.yml` сам создаёт тег `vX.Y.Z` и GitHub-релиз из верхней записи `CHANGELOG.md`.
- Все проверки проекта — в `scripts/check.sh`, CI запускает его на каждый PR. Новое поведение — новый тест.
- Секреты — только в переменных окружения и секретах GitHub/хостинга, никогда в коде.

## IdeaHub
- Проект — реализация идеи из IdeaHub, номер в `.ideahub` (`idea_id`). Коннектор: MCP `ideahub`.
- Начиная работу: `get_idea(idea_id)` — бриф, план и журнал. Работай по плану MVP, не расширяй объём без согласия владельца.
- После каждого мержа: `append_note(idea_id, "vX.Y.Z — название (PR <ссылка>): что вошло")`.
  Статус идеи: `in_progress` пока идёт работа, `done` когда MVP готов; `repo_url` — ссылка на этот репозиторий.
- Отложенные мысли и идеи по улучшению — тоже в IdeaHub (`append_note`), а не в коде.

## Первый PR после создания из шаблона (0.1.0)
1. Заменить `PROJECT_NAME` здесь и в `README.md`, заполнить «О проекте».
2. Вписать `idea_id` в `.ideahub`.
3. Каркас проекта под выбранный стек, `.gitignore` под него, `scripts/check.sh` с реальными проверками
   и установка инструментов в `.github/workflows/ci.yml`.
4. Запись `0.1.0` в `CHANGELOG.md`.
